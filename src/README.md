# SLOCloud Source Directory

This directory is the application web root. Point your web server document root here and run the setup wizard. Deploy **only** this directory to production -- do not expose the repository root.

## Directory Structure

```text
src/
+-- index.php                 # Application entry point / front controller
+-- login.php                 # Admin login page
+-- logout.php                # Session termination
+-- .htaccess                 # Apache security rules and routing
+-- VERSION                   # Current version string
+-- PATCH_NOTES.md            # Release history
+-- EULA.md                   # End-user license agreement
+-- administration/           # Admin pages (terms, programs, courses, students, reports)
+-- api/                      # Internal AJAX endpoints
+-- lti/                      # LTI 1.1/1.3 launch and JWKS endpoints
+-- saml/                     # SAML 2.0 single sign-on: sso (start), acs (sign-in), metadata, slo (logout)
+-- setup/                    # Web-based setup wizard (disable after install)
+-- sessions/                 # PHP session storage (write access required)
+-- vpat/                     # Accessibility conformance reports (WCAG 2.2)
+-- config/
|   +-- config.yaml           # Generated by setup wizard (do not commit)
|   +-- key.yaml              # Encryption master keys (do not commit)
|   +-- config.yaml.template  # Default values merged automatically on load
|   +-- key.yaml.example      # Key file template for reference
|   +-- .htaccess             # Blocks web access to all .yaml files
+-- system/
    +-- Core/                 # Config, Database, Logger, ThemeLoader, Encryption
    +-- database/
    |   +-- schema.sql        # MySQL schema
    |   +-- schema_mssql.sql  # SQL Server schema
    |   +-- migrations/       # Incremental schema migrations
    +-- includes/             # Shared page components (init, session, messages)
    +-- lib/                  # Bundled third-party PHP libraries (SAML); see lib/README.md
    +-- plugins/              # Plugin framework and local plugins
    +-- scripts/              # CLI maintenance scripts
```

## Installation

Browse to `https://yourdomain.edu/setup/` after deploying. The wizard handles database creation, schema installation, encryption key generation, and config file writing.

Full instructions: [../docs/SETUP_GUIDE.md](../docs/SETUP_GUIDE.md)

### Local Development Server

```powershell
# From repository root
php -S localhost:8000 -t src/
```

Access at `http://localhost:8000/`. Use `app.debug_mode: true` and `app.php_error_mode: display` in `config.yaml` during development.

## Configuration

The setup wizard generates `config/config.yaml`. On every request, the application merges `config.yaml.template` defaults with your `config.yaml` so new config keys from updates take effect automatically without manual edits.

Sensitive values (database password, SMTP password, LTI consumer secret, student encryption key) are stored encrypted (`ENC:...`) and decrypted at runtime using `key.yaml`.

See [config/README.md](config/README.md) for the full two-file encryption architecture.

## Security Notes

- `config/` is protected by `.htaccess` -- `.yaml` files return 403 to web requests.
- For IIS, add an equivalent `web.config` to `config/` blocking `.yaml`, `.sql`, and `.log` extensions.
- The `setup/` wizard disables itself once `config.yaml` exists. Remove the directory after installation for defense in depth.
- Session files are stored in `sessions/` -- the web server process needs write access.
- See [../docs/concepts/SECURITY.md](../docs/concepts/SECURITY.md) for full security requirements.

## Key Rotation

Encryption keys can be rotated from **Administration > System > Configuration** without filesystem access. All key rotations require Maintenance Mode to be enabled and saved first. The student lookup key can also be created on legacy installations from the same panel; student IDs are decrypted and rehashed without changing the encrypted student data.
