# SLOCloud 5.1.0 accessibility verification

Date: July 19, 2026

## Automated source and regression checks

- `php tests/accessibility_test.php` passed.
- `php tests/security_test.php` passed, including the deny-by-default route matrix.
- `php tests/reporting_test.php` passed.
- PHP syntax checks passed for the changed application, LTI, session, setup, theme, and test files.
- `git diff --check` passed; reported messages are line-ending notices rather than whitespace errors.

The accessibility regression test checks shared focus treatment, contrast ratios for the shared focus/control colors, minimum target sizing, reduced motion, forced colors, reflow safeguards, landmarks, bypass links, personal-input purpose, validation associations, named dialogs, status messages, CSRF-protected timeout extension, and current-version report links.

The completed source inventory also checks all 55 Level A/AA matrix entries, rejects positive tab order, non-native scripted controls, unscoped table headers, undisclosed new-window links, and in-scope image/media elements, and verifies that both current VPATs contain only `Supports` or `Not Applicable` results.

## Browser behavior verification

The repository test page at `tests/fixtures/accessibility-page.html` loads the production `system/accessibility.css` and `system/accessibility.js` with representative form, table, status, navigation, responsive-layout, and Bootstrap-dialog markup.

Verified in the in-app Chromium browser:

- the page exposes one named main region, ordered headings, a named navigation region, named/scoped table headers, and a polite DataTables-style status message;
- submitting an invalid required email field creates and focuses an alert headed “Correct the following error,” links the summary to the field, sets the field error text, and preserves its accessible name;
- an otherwise unnamed Bootstrap modal receives its visible title as its accessible name, and focus returns to the Open dialog button after closing;
- the session warning opens as a modal dialog, moves focus to Continue session, announces the countdown, discloses the timeout behavior, and closes after a successful explicit extension;
- session-extension controls remain keyboard-operable and the dialog prevents accidental Escape dismissal.

## Implementation evidence added in 5.1.0

- Shared error identification/suggestion and linked summary behavior applies to native forms across all loaded themes.
- Admin session extension uses a POST-only, CSRF-validated endpoint; the warning starts two minutes before the two-hour timeout and has no extension-count limit.
- LTI extension is POST-only and CSRF validated. Activity-based keepalive no longer extends an idle launch indefinitely; a two-minute warning is presented before the eight-hour LTI limit.
- Individual LTI assessment, assessment-method, and improvement-strategy changes provide Undo actions; bulk changes require confirmation.
- The global term filter requires an explicit Apply action instead of navigating on selection.
- DataTables information/processing messages and routine success messages use status semantics; urgent failures use alerts.
- Missing dialog names, table captions/scopes, close-button names, heading levels, and identity-field autocomplete tokens identified by the source audit were corrected.
- Admin sidebar disclosure links were replaced with native buttons whose `aria-expanded` state is synchronized with uniquely identified controlled regions.
- A complete administration Site Map was added and exposed consistently across supported themes as the alternate way to locate pages.
- Dynamic report-builder focus is restored after adding, removing, moving, or rerendering controls; its narrow layout collapses to one column and report cells no longer clip content.
- Fixed notification containers reflow at narrow widths and move to the opposite viewport edge if they would cover the newly focused control.
- Low-contrast custom muted, informational, success, and warning colors were replaced and added to computed contrast regression checks.
- All application-authored new-window links disclose the context change, and decorative icons are hidden from assistive technology.

## Conformance result and additional release evidence

The code and current regression evidence support every applicable WCAG 2.2 Level A/AA criterion in the administration and LTI scopes; both current VPATs claim Level AA for their evaluated SLOCloud scope.

Assistive-technology support is delegated to the user's browser; the application's responsibility is correct semantics, names, focus handling and contrast, which the checks above cover.
